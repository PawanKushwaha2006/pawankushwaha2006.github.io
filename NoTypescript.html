01

Introduction to TypeScript

TypeScript is a statically typed superset of JavaScript created by Anders Hejlsberg at Microsoft in 2012. It compiles down to plain JavaScript, meaning it runs anywhere JS runs — browsers, Node.js, Deno, Bun.

The key idea: add optional types to JavaScript so mistakes are caught at compile time, not runtime. TypeScript also enhances IDE tooling with autocomplete, refactoring, and inline documentation.

🔒
Type Safety
Catch bugs before running code — at compile time.
🧠

Autocomplete, inline errors, and refactoring support.
📦
JS Compatible
Any valid JavaScript is valid TypeScript.
🏗️

// hello.ts
function greet(name: string): string {
    return `Hello, ${name}!`;
}

console.log(greet("World"));   // ✅ OK
console.log(greet(42));        // ❌ Error: number not assignable to string

04

Type Inference

TypeScript can automatically infer types from values — you don't always need to annotate explicitly.

// TypeScript infers these types automatically
let city     = "Tokyo";       // inferred: string
let count    = 42;            // inferred: number
let isOpen   = false;         // inferred: boolean
let nums     = [1, 2, 3];    // inferred: number[]

// Function return type is inferred
function double(x: number) {
    return x * 2;              // return type: number
}

// Use explicit annotation when needed for clarity
let result: number = double(10);
Best Practice Let TypeScript infer when the type is obvious. Annotate function parameters, return types, and public APIs explicitly.
05

Union & Intersection Types

Union Types — A or B

let id: string | number;
id = "abc-123";   // ✅
id = 42;          // ✅
id = true;        // ❌ boolean not in union

// Union in function parameters
function format(value: string | number): string {
    return `Value: ${value}`;
}

Intersection Types — A and B

type Named   = { name: string };
type Aged    = { age: number };
type Person  = Named & Aged;  // has BOTH fields

const p: Person = { name: "Alice", age: 30 }; // ✅
06

Literal Types

Literal types restrict a variable to a specific set of exact values, not just a broad type.

// String literals
type Direction = "north" | "south" | "east" | "west";
let dir: Direction = "north";  // ✅
dir = "up";                      // ❌ not in literal union

// Numeric literals
type DiceRoll = 1 | 2 | 3 | 4 | 5 | 6;

// Boolean literal
type TrueOnly = true;

// In function signatures
function move(dir: Direction, steps: number): void {
    console.log(`Moving ${steps} steps ${dir}`);
}
07

Tuples

A tuple is a fixed-length array where each position has a specific type.

// Tuple declaration
let point: [number, number] = [10, 20];

// Mixed type tuple
let record: [string, number, boolean] = ["Alice", 30, true];

// Named tuples (TypeScript 4+)
type RGB = [red: number, green: number, blue: number];
const color: RGB = [255, 128, 0];

// Destructuring
const [r, g, b] = color;
// r=255, g=128, b=0
08

Enums

// Numeric enum (auto-increments from 0)
enum Direction { Up, Down, Left, Right }
console.log(Direction.Up);    // → 0
console.log(Direction.Right); // → 3

// String enum (explicit values)
enum Status {
    Active   = "ACTIVE",
    Inactive = "INACTIVE",
    Pending  = "PENDING"
}

function checkStatus(s: Status) {
    if (s === Status.Active) console.log("User is active");
}

// const enum — inlined at compile time (faster)
const enum Size { Small = 1, Medium = 2, Large = 3 }

any, unknown, never, void

TypeMeaningSafe?
anyOpt out of type checking entirely❌ Unsafe
unknownCan be anything, but must narrow before use✅ Safe
neverA value that never occurs (unreachable code)✅ Safe
voidFunction returns no value✅ Safe
// any — avoid when possible
let x: any = "hello";
x = 42; x.anything(); // no errors!

// unknown — safer alternative to any
let val: unknown = getUserInput();
if (typeof val === "string") {
    console.log(val.toUpperCase()); // ✅ narrowed
}

// never — function that always throws
function fail(msg: string): never {
    throw new Error(msg);
}

// void — no return value
function log(msg: string): void {
    console.log(msg);
}
10

Interfaces

Interfaces define the shape of an object. They are purely a compile-time construct — no runtime overhead.

interface User {
    id:       number;
    name:     string;
    email?:   string;         // optional property
    readonly createdAt: Date; // cannot be changed
}

const user: User = {
    id: 1,
    name: "Alice",
    createdAt: new Date()
};

// Interface extension
interface Admin extends User {
    role: "admin" | "superadmin";
    permissions: string[];
}

// Interface for functions
interface Formatter {
    (input: string): string;
}
Interface vs Type Alias Interfaces are extendable via extends and support declaration merging. Type aliases support union types and computed types. Prefer interfaces for object shapes, types for everything else.

Type Aliases

// Simple alias
type ID     = string | number;
type Point  = { x: number; y: number };
type Callback = (err: Error | null) => void;

// Mapped type
type Readonly<T> = {
    readonly [K in keyof T]: T[K];
};

// Conditional type
type IsString<T> = T extends string ? true : false;
type A = IsString<string>;  // true
type B = IsString<number>;  // false
12

Classes

class Animal {
    // Access modifiers: public, private, protected
    public    name:  string;
    private   age:   number;
    protected sound: string;
    readonly  id:    number;

    // Shorthand constructor
    constructor(public species: string, name: string) {
        this.name = name;
        this.id   = Math.random();
    }

    // Method
    speak(): void {
        console.log(`${this.name} says ${this.sound}`);
    }

    // Getter / Setter
    get info(): string     { return `${this.name} (${this.species})`; }
    set info(v: string)   { this.name = v; }
}

// Inheritance
class Dog extends Animal {
    constructor(name: string) {
        super("Dog", name);
        this.sound = "Woof!";
    }
    fetch() { console.log("Fetching!"); }
}

// Abstract class
abstract class Shape {
    abstract area(): number;
    describe() { console.log(`Area: ${this.area()}`); }
}
13

Functions

// Typed parameters and return type
function add(a: number, b: number): number {
    return a + b;
}

// Optional parameter
function greet(name: string, title?: string): string {
    return title ? `${title} ${name}` : name;
}

// Default parameter
function power(base: number, exp: number = 2): number {
    return Math.pow(base, exp);
}

// Rest parameters
function sum(...nums: number[]): number {
    return nums.reduce((a, b) => a + b, 0);
}

// Arrow function
const multiply = (a: number, b: number): number => a * b;

// Function overloading
function parse(input: string): string;
function parse(input: number): number;
function parse(input: any): any { return input; }
14

Generics

Generics allow writing reusable, type-safe code that works with multiple types without losing type information.

// Generic function
function identity<T>(value: T): T {
    return value;
}
identity<string>("hello");   // explicit
identity(42);               // inferred T = number

// Generic interface
interface ApiResponse<T> {
    data:    T;
    status:  number;
    message: string;
}
const res: ApiResponse<User[]> = { data: [], status: 200, message: "ok" };

// Generic constraint
function getLength<T extends { length: number }>(item: T): number {
    return item.length;
}
getLength("hello");     // ✅  string has .length
getLength([1,2,3]);     // ✅  array has .length

// Multiple type params
function pair<A, B>(a: A, b: B): [A, B] { return [a, b]; }
15

Type Narrowing & Guards

TypeScript narrows the type within conditionals — it knows more specific types inside if-blocks.

// typeof guard
function printId(id: string | number) {
    if (typeof id === "string") {
        console.log(id.toUpperCase()); // id is string here
    } else {
        console.log(id.toFixed(2));   // id is number here
    }
}

// instanceof guard
if (err instanceof Error) {
    console.log(err.message);
}

// in operator guard
if ("name" in user) {
    console.log(user.name);
}

// Custom type guard
function isString(val: unknown): val is string {
    return typeof val === "string";
}

// Discriminated union
type Shape =
    | { kind: "circle";    radius: number  }
    | { kind: "rectangle"; width: number; height: number };

function area(s: Shape): number {
    switch (s.kind) {
        case "circle":    return Math.PI * s.radius ** 2;
        case "rectangle": return s.width * s.height;
    }
}

Utility Types

TypeScript ships with built-in generic utility types for common type transformations.

interface User { id: number; name: string; email: string; }

Partial<User>          // all fields optional
Required<User>         // all fields required
Readonly<User>         // all fields readonly
Pick<User, "id" | "name">    // only id and name
Omit<User, "email">    // everything except email
Record<string, number> // {[key:string]: number}
Exclude<"a"|"b"|"c", "a">    // "b" | "c"
Extract<"a"|"b", "a"|"c">     // "a"
NonNullable<string | null>  // string
ReturnType<typeof add>      // infer return type of add
Parameters<typeof add>      // infer param types of add
Awaited<Promise<string>>     // string

Modules

// ── math.ts ──
export const PI = 3.14159;
export function add(a: number, b: number) { return a + b; }
export default function multiply(a: number, b: number) { return a*b; }

// ── app.ts ──

import * as Math from "./math";          // namespace import
import type { User } from "./types";    // type-only import

// Re-export
export { add, PI } from "./math";
export * from "./math";

Decorators

Decorators are a stage-3 proposal (experimental in TS). Enable with "experimentalDecorators": true in tsconfig.

// Class decorator
function Sealed(constructor: Function) {
    Object.seal(constructor);
}

@Sealed
class BankAccount {
    balance: number = 0;
}

// Method decorator
function log(target: any, key: string, desc: PropertyDescriptor) {
    const original = desc.value;
    desc.value = function(...args: any[]) {
        console.log(`Calling ${key}`);
        return original.apply(this, args);
    };
}

class Service {
    @log
    process() { /* ... */ }
}

tsconfig.json

The tsconfig.json file configures how the TypeScript compiler behaves.

{
  "compilerOptions": {
    "target":          "ES2022",     // output JS version
    "module":          "ESNext",     // module system
    "lib":             ["ES2022", "DOM"],
    "outDir":          "./dist",     // compiled output
    "rootDir":         "./src",

    "strict":          true,         // all strict checks
    "noImplicitAny":   true,
    "strictNullChecks":true,

    "esModuleInterop": true,
    "declaration":     true,         // emit .d.ts files
    "sourceMap":        true,

    "paths": {
      "@/*": ["./src/*"]              // path aliases
    }
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}
Always enable strict mode Set "strict": true in every project. It enables strictNullChecks, noImplicitAny, and 6 other checks that catch the most common bugs.
