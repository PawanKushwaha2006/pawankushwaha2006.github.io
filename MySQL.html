01

Introduction to MySQL

MySQL is an open-source Relational Database Management System (RDBMS) originally developed by Michael Widenius and David Axmark in 1995. It is now owned by Oracle Corporation and is the backbone of countless web applications, including WordPress, Facebook (early days), Twitter, and YouTube.

MySQL stores data in structured tables with rows and columns, and uses SQL (Structured Query Language) to interact with that data. It follows the ACID model for reliable transactions.

🗄️
Relational Model
Data stored in structured tables with defined relationships.
⚡
High Performance
Optimized for read-heavy workloads, caching, and fast queries.
🔒
ACID Compliant
Atomicity, Consistency, Isolation, Durability guaranteed.
🌐
Cross Platform
Runs on Linux, macOS, Windows, and cloud platforms.

# Windows — download installer from mysql.com

SQL is Case-Insensitive SQL keywords like SELECT, FROM, and WHERE are case-insensitive. Writing them in UPPERCASE is a widely used convention for readability. Table and column names may be case-sensitive depending on the operating system.

Working with Databases

A database is a container for tables and related objects. You must create and select a database before creating tables.

-- Create a new database
CREATE DATABASE shop;

-- Create only if it doesn't exist
CREATE DATABASE IF NOT EXISTS shop;

-- Create with character set (recommended)
CREATE DATABASE shop
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

-- Select the database to use
USE shop;

-- Rename a database (not directly supported in MySQL)
-- Workaround: dump and restore with new name

-- Drop (delete) a database — IRREVERSIBLE!
DROP DATABASE shop;
DROP DATABASE IF EXISTS shop;
DROP is Permanent DROP DATABASE deletes everything inside it — all tables, data, views, and stored procedures. Always back up your data before dropping a database.

Creating & Modifying Tables

Tables are the core structure in MySQL. Each column has a name, data type, and optional constraints like NOT NULL, UNIQUE, or DEFAULT.

CREATE TABLE

CREATE TABLE users (
  id         INT          NOT NULL AUTO_INCREMENT,
  username   VARCHAR(50)  NOT NULL UNIQUE,
  email      VARCHAR(100) NOT NULL UNIQUE,
  password   VARCHAR(255) NOT NULL,
  age        TINYINT      DEFAULT 0,
  is_active  TINYINT(1)   DEFAULT 1,
  created_at TIMESTAMP   DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP   DEFAULT CURRENT_TIMESTAMP
                           ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id)
);

-- Table with Foreign Key
CREATE TABLE orders (
  id         INT           NOT NULL AUTO_INCREMENT,
  user_id    INT           NOT NULL,
  total      DECIMAL(10,2) NOT NULL,
  status     ENUM('pending','paid','cancelled') DEFAULT 'pending',
  created_at TIMESTAMP    DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  FOREIGN KEY (user_id) REFERENCES users(id)
    ON DELETE CASCADE ON UPDATE CASCADE
);

ALTER TABLE

-- Add a column
ALTER TABLE users ADD COLUMN phone VARCHAR(20);

-- Modify a column's type
ALTER TABLE users MODIFY COLUMN age SMALLINT;

-- Rename a column (MySQL 8.0+)
ALTER TABLE users RENAME COLUMN phone TO mobile;

-- Drop a column
ALTER TABLE users DROP COLUMN mobile;

-- Rename a table
RENAME TABLE users TO customers;

-- Drop a table
DROP TABLE IF EXISTS orders;

-- Truncate — delete all rows but keep structure
TRUNCATE TABLE orders;

CRUD Operations

The four fundamental operations: Create (INSERT), Read (SELECT), Update (UPDATE), and Delete (DELETE).

INSERT — Create Rows

-- Insert a single row
INSERT INTO users (username, email, password)
VALUES ('alice', 'alice@example.com', 'hashed_pw');

-- Insert multiple rows at once
INSERT INTO users (username, email, password) VALUES
  ('bob',     'bob@example.com',     'hashed_pw2'),
  ('charlie', 'charlie@example.com', 'hashed_pw3');

-- Insert or update if duplicate key exists
INSERT INTO users (id, username, email) VALUES (1, 'alice', 'new@mail.com')
ON DUPLICATE KEY UPDATE email = VALUES(email);

UPDATE — Modify Rows

-- Update specific rows (ALWAYS use WHERE!)
UPDATE users
SET email = 'alice_new@example.com', age = 31
WHERE id = 1;

-- Update multiple rows matching a condition
UPDATE orders
SET status = 'cancelled'
WHERE status = 'pending' AND created_at < '2024-01-01';

DELETE — Remove Rows

-- Delete specific row
DELETE FROM users WHERE id = 5;

-- Delete with multiple conditions
DELETE FROM orders
WHERE status = 'cancelled' AND user_id = 3;
Always Use WHERE with UPDATE / DELETE Running UPDATE users SET active = 0 without a WHERE clause will update EVERY row. Running DELETE FROM users will delete ALL rows. Double-check before executing.

SELECT & Filtering

SELECT is the most powerful and commonly used SQL command. It retrieves data from one or more tables with filtering, sorting, and limiting capabilities.

-- Select all columns
SELECT * FROM users;

-- Select specific columns
SELECT id, username, email FROM users;

-- Column aliases
SELECT username AS 'User Name', email AS 'Contact' FROM users;

-- WHERE clause with operators
SELECT * FROM users WHERE age >= 18;
SELECT * FROM users WHERE is_active = 1 AND age < 40;
SELECT * FROM users WHERE username = 'alice' OR username = 'bob';

-- IN — match multiple values
SELECT * FROM users WHERE id IN (1, 3, 7);

-- BETWEEN — range filter
SELECT * FROM orders WHERE total BETWEEN 100 AND 500;

-- LIKE — pattern matching
SELECT * FROM users WHERE email LIKE '%@gmail.com';
SELECT * FROM users WHERE username LIKE 'al%';   -- starts with al
SELECT * FROM users WHERE username LIKE '_ob';   -- any char + ob

-- NULL checks
SELECT * FROM users WHERE phone IS NULL;
SELECT * FROM users WHERE phone IS NOT NULL;

-- ORDER BY — sort results
SELECT * FROM users ORDER BY age DESC;
SELECT * FROM users ORDER BY username ASC, age DESC;

-- LIMIT / OFFSET — pagination
SELECT * FROM users LIMIT 10;
SELECT * FROM users LIMIT 10 OFFSET 20;  -- page 3 (20 skipped)

-- DISTINCT — remove duplicates
SELECT DISTINCT country FROM users;
08

JOINs

JOINs combine rows from two or more tables based on a related column. They are one of the most powerful features of relational databases.

-- INNER JOIN — rows that match in BOTH tables
SELECT u.username, o.id, o.total
FROM users u
INNER JOIN orders o ON u.id = o.user_id;

-- LEFT JOIN — all rows from left + matching from right
SELECT u.username, o.total
FROM users u
LEFT JOIN orders o ON u.id = o.user_id;
-- users with no orders will show NULL for o.total

-- RIGHT JOIN — all rows from right + matching from left
SELECT u.username, o.id
FROM users u
RIGHT JOIN orders o ON u.id = o.user_id;

-- Joining 3 tables
SELECT u.username, o.total, p.name AS product
FROM users u
INNER JOIN orders o    ON u.id = o.user_id
INNER JOIN products p  ON o.product_id = p.id;
JOIN TypeReturns
INNER JOINOnly rows with matches in both tables
LEFT JOINAll rows from left table + matched rows from right (NULL if no match)
RIGHT JOINAll rows from right table + matched rows from left (NULL if no match)
CROSS JOINCartesian product — every combination of rows
SELF JOINA table joined with itself (e.g. employees and their managers)

Aggregate Functions & GROUP BY

Aggregate functions compute a single result from a set of rows. GROUP BY groups rows sharing a value so aggregates can be applied per group.

-- COUNT — count rows
SELECT COUNT(*) FROM users;
SELECT COUNT(email) FROM users;  -- ignores NULLs

-- SUM, AVG, MIN, MAX
SELECT SUM(total) FROM orders;
SELECT AVG(age)   FROM users;
SELECT MIN(total), MAX(total) FROM orders;

-- GROUP BY — aggregate per group
SELECT status, COUNT(*) AS count, SUM(total) AS revenue
FROM orders
GROUP BY status;

-- HAVING — filter groups (like WHERE but for aggregates)
SELECT user_id, COUNT(*) AS order_count
FROM orders
GROUP BY user_id
HAVING order_count > 5;

-- Full example with WHERE + GROUP BY + HAVING + ORDER BY
SELECT u.username, COUNT(o.id) AS orders, SUM(o.total) AS total_spent
FROM users u
JOIN orders o ON u.id = o.user_id
WHERE o.status = 'paid'
GROUP BY u.id
HAVING total_spent > 1000
ORDER BY total_spent DESC
LIMIT 10;
WHERE vs HAVING WHERE filters individual rows before grouping. HAVING filters groups after GROUP BY is applied. You cannot use aggregate functions in WHERE.
10

Subqueries

A subquery is a query nested inside another query. It can be used in SELECT, FROM, WHERE, and HAVING clauses.

-- Subquery in WHERE (scalar)
SELECT * FROM orders
WHERE total > (SELECT AVG(total) FROM orders);

-- Subquery with IN
SELECT * FROM users
WHERE id IN (
  SELECT user_id FROM orders WHERE status = 'paid'
);

-- Subquery in FROM (derived table)
SELECT avg_data.user_id, avg_data.avg_order
FROM (
  SELECT user_id, AVG(total) AS avg_order
  FROM orders
  GROUP BY user_id
) AS avg_data
WHERE avg_data.avg_order > 200;

-- EXISTS — check if subquery returns any rows
SELECT * FROM users u
WHERE EXISTS (
  SELECT 1 FROM orders o WHERE o.user_id = u.id
);

Indexes

Indexes dramatically speed up data retrieval at the cost of slightly slower writes and extra storage. They're like a book's index — instead of reading every page, you jump directly to what you need.

-- Create a simple index
CREATE INDEX idx_email ON users(email);

-- Create a unique index
CREATE UNIQUE INDEX idx_username ON users(username);

-- Composite index (multi-column)
CREATE INDEX idx_status_date ON orders(status, created_at);

-- Show indexes on a table
SHOW INDEX FROM users;

-- Drop an index
DROP INDEX idx_email ON users;

-- EXPLAIN — see how MySQL executes a query
EXPLAIN SELECT * FROM users WHERE email = 'alice@example.com';
When to Add an Index Add indexes on columns frequently used in WHERE, JOIN ON, and ORDER BY clauses. Avoid over-indexing write-heavy tables — each index slows down INSERT, UPDATE, and DELETE operations.
12

Views

A view is a virtual table based on a stored SELECT query. Views simplify complex queries, improve security by exposing only certain columns, and provide a consistent interface to the data.

-- Create a view
CREATE VIEW active_users AS
SELECT id, username, email
FROM users
WHERE is_active = 1;

-- Query the view like a table
SELECT * FROM active_users;

-- Create or replace an existing view
CREATE OR REPLACE VIEW active_users AS
SELECT id, username, email, created_at
FROM users
WHERE is_active = 1;

-- Drop a view
DROP VIEW IF EXISTS active_users;

-- List all views in current database
SHOW FULL TABLES WHERE Table_type = 'VIEW';

Transactions

Transactions group multiple SQL statements into a single all-or-nothing unit. If any step fails, everything is rolled back — ensuring data integrity (ACID).

-- Basic transaction structure
START TRANSACTION;

UPDATE accounts SET balance = balance - 500 WHERE id = 1;
UPDATE accounts SET balance = balance + 500 WHERE id = 2;

-- If all went well, commit
COMMIT;

-- If something went wrong, rollback everything
ROLLBACK;

-- SAVEPOINT — partial rollback
START TRANSACTION;
INSERT INTO orders (user_id, total) VALUES (1, 200);
SAVEPOINT order_saved;

INSERT INTO order_items (order_id, product_id) VALUES (LAST_INSERT_ID(), 5);
-- If this fails:
ROLLBACK TO order_saved;  -- undo only to savepoint

COMMIT;

-- Turn off autocommit
SET autocommit = 0;

Stored Procedures & Functions

Stored procedures are reusable blocks of SQL logic stored in the database. Functions are similar but must return a value.

-- Create a stored procedure
DELIMITER //

CREATE PROCEDURE GetUserOrders(IN userId INT)
BEGIN
  SELECT o.id, o.total, o.status, o.created_at
  FROM orders o
  WHERE o.user_id = userId
  ORDER BY o.created_at DESC;
END //

DELIMITER ;

-- Call the procedure
CALL GetUserOrders(3);

-- Drop a procedure
DROP PROCEDURE IF EXISTS GetUserOrders;

-- Create a stored function
DELIMITER //

CREATE FUNCTION CalcTax(price DECIMAL(10,2)) RETURNS DECIMAL(10,2)
DETERMINISTIC
BEGIN
  RETURN price * 1.18;  -- 18% tax
END //

DELIMITER ;

-- Use the function in a query
SELECT product_name, CalcTax(price) AS price_with_tax FROM products;

Triggers

Triggers are automatic SQL procedures that execute before or after an INSERT, UPDATE, or DELETE on a table. They're useful for auditing, enforcing rules, and maintaining derived data.

DELIMITER //

-- Trigger: log every deleted user to an audit table
CREATE TRIGGER after_user_delete
AFTER DELETE ON users
FOR EACH ROW
BEGIN
  INSERT INTO audit_log (action, user_id, deleted_at)
  VALUES ('DELETE', OLD.id, NOW());
END //

-- Trigger: prevent negative balances (BEFORE UPDATE)
CREATE TRIGGER before_balance_update
BEFORE UPDATE ON accounts
FOR EACH ROW
BEGIN
  IF NEW.balance < 0 THEN
    SIGNAL SQLSTATE '45000'
      SET MESSAGE_TEXT = 'Balance cannot be negative';
  END IF;
END //

DELIMITER ;

-- Show all triggers
SHOW TRIGGERS;

-- Drop a trigger
DROP TRIGGER IF EXISTS after_user_delete;
OLD and NEW Keywords Inside triggers, OLD.column refers to the value before the change, and NEW.column refers to the new value. OLD is available in UPDATE and DELETE triggers. NEW is available in INSERT and UPDATE triggers.

Users & Permissions

MySQL has a built-in permission system. Always create specific users with only the privileges they need — never use the root account for your application.

-- Create a new user
CREATE USER 'appuser'@'localhost' IDENTIFIED BY 'StrongPassword!123';

-- Create user accessible from any host
CREATE USER 'appuser'@'%' IDENTIFIED BY 'StrongPassword!123';

-- Grant all privileges on a specific database
GRANT ALL PRIVILEGES ON shop.* TO 'appuser'@'localhost';

-- Grant specific privileges only
GRANT SELECT, INSERT, UPDATE, DELETE ON shop.* TO 'appuser'@'localhost';

-- Read-only user
GRANT SELECT ON shop.* TO 'readonly'@'localhost';

-- Apply the privilege changes
FLUSH PRIVILEGES;

-- Show grants for a user
SHOW GRANTS FOR 'appuser'@'localhost';

-- Revoke privileges
REVOKE INSERT, UPDATE ON shop.* FROM 'appuser'@'localhost';

-- Change a user's password
ALTER USER 'appuser'@'localhost' IDENTIFIED BY 'NewPassword!456';

-- Drop a user
DROP USER IF EXISTS 'appuser'@'localhost';
